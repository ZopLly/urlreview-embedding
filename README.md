# URL Review

Терминальное приложение на C для ручной проверки категорий сайтов. Полностью локально: без API, загрузки сайтов и нейросетевой разметки. Это первая рабочая основа; поиск похожих через эмбеддинги — следующий этап.

## Быстро попробовать

В терминале из папки проекта:

```sh
./scripts/run-demo.sh
```

Скрипт собирает программу и открывает **только вымышленные данные**. Результаты сохраняются в `results/demo-review.csv`; при повторном запуске работа продолжается из этой копии. Для нового демо укажите другое имя выходного файла. Учебный `main.c` в другом проекте не менялся.

Требования: Linux, компилятор C17, make, pkg-config и ncursesw. На данном компьютере они установлены. На другом Arch/CachyOS нужны `base-devel`, `pkgconf`, `ncurses`; на Debian/Ubuntu — `build-essential`, `pkg-config`, `libncurses-dev`. Автоматической установки и сетевых запросов в приложении нет.

## Сборка и проверки

```sh
make
make test
make sanitize
```

Тесты используют C и стандартную библиотеку Python 3, включая PTY. Все наборы вымышленные. `make sanitize` запускает ASan/UBSan; LeakSanitizer по умолчанию выключен из-за ограничения ptrace в среде разработки. В обычной среде можно запустить `ASAN_OPTIONS=detect_leaks=1 make sanitize`.

## Работа со своим файлом

Запускайте самостоятельно. Приложение читает указанные пути; помощник при разработке настоящие CSV не открывал.

```sh
./url-review '/путь/исходник.csv' '/путь/рабочая-копия.csv' --encoding windows-1251 --delimiter ';'
```

Для UTF-8 параметр кодировки можно опустить. Допустимы разделители `;`, `,`, `tab`. Кодировку нужно выбирать по фактическому файлу: Linux и Windows умеют работать с обеими. Программа не угадывает её и не заменяет непредставимые символы на `?`.

Проверка без интерфейса и без создания рабочей копии:

```sh
./url-review --check '/путь/исходник.csv' --encoding windows-1251 --delimiter ';'
```

Обязательны уникальные заголовки `domain`, `class`, `label`, `action`, `description`, в любом порядке. Дополнительные столбцы сохраняются. Кавычки, двойные кавычки внутри полей, CRLF/LF, UTF-8 BOM, пустые и многострочные поля поддерживаются. Одна CSV-запись может занимать несколько физических строк. Лимит входного файла — 256 МиБ; текст хранится в памяти целиком, поэтому нужен запас RAM.

## Управление

Требуется окно не меньше 65×18; удобнее 100×30 и больше. Клавиши команд — в английской раскладке.

| Экран | Клавиши |
|---|---|
| Запись | `1` OK, `2` ERROR, `3` NOT_DESC |
| Описание | стрелки, Page Up / Page Down, Home / End; также J/K |
| Запись | S — отложить, B — назад по истории, H/F1 — справка, Q — выход |
| Категории | стрелки/J/K; Space отмечает, повторное нажатие снимает |
| Категории | номер и Enter — отметить категорию по постоянному номеру |
| Категории | Enter без номера — перейти к подтверждению; C — очистить |
| Категории | H/F1 — критерии выделенной категории; Escape — отменить черновик |
| Подтверждение | Enter — сохранить, Escape — изменить категории |
| Черновик, Q | S — перейти к сохранению; D — выйти без черновика; C — продолжить |
| Итог прохода | R — снова открыть отложенные, B — вернуться к последней записи, V — просмотр с первой |

После подтверждения сохраняется вся рабочая копия, затем открывается следующая непроверенная запись. Индикатор считает непустые допустимые action; возврат и изменение существующего решения не завышают прогресс. У уже проверенных записей в исходнике action сохраняется, они пропускаются при обычном проходе.

«Отложить» не пишет статус: action остаётся пустым. Отложенные пропускаются до конца текущего прохода; R запускает новый проход, при новом запуске они тоже доступны. История B и отложенные — состояние текущего сеанса. Ctrl+C/SIGTERM прекращают сеанс, не сохраняют текущий черновик; подтверждённые решения уже записаны.

## Правила разметки

- `OK`: class верен; label — дополнительные категории или пусто.
- `ERROR`: class неверен; label — правильные категории или пусто, если подходящей категории нет.
- `NOT_DESC`: описание недостаточно или считано неверно. **Предоставленный PDF требует заполнить label установленной категорией. По явному уточнению пользователя программа допускает пустой label. Это отличие от письменной инструкции, которое нужно учитывать при сдаче.**
- В label записываются только точные английские коды, несколько — через запятую. Русские пояснения и номера существуют только на экране.
- Новые категории не придумываются. `electronic_commerce` и другие спорные значения class автоматически не исправляются. Справочник не решает вопросы, оставленные на уточнение работодателю.

`data/categories.tsv` содержит 59 категорий и критерии из предоставленного «Категории train.pdf»; номера определены порядком строк. Поля TSV: код, русское пояснение (либо исходный код, если пояснения нет), включения, исключения. Перегенерация при изменении исходного справочника возможна через `scripts/extract_guide.py` и Poppler; для обычного запуска PDF не требуется. Спорные гипотезы из журнала не включены. Справочник — правила данного задания, не универсальная таксономия.

## Как устроено сохранение

Исходник не перезаписывается. Для рабочей копии нужен **другой путь**; при первом запуске она создаётся. При продолжении проверяются заголовки, количество и порядок записей и точное совпадение всех столбцов, кроме action/label. Поэтому повторяющиеся домены допустимы, но пересортированная/изменённая извне копия может быть отклонена. Перезапускайте с той же кодировкой и разделителем.

Сохраняются только action/label; содержимое остальных полей не изменяется. Физическое оформление CSV может нормализоваться: кавычки вокруг полей и переводы между записями. Переносы внутри описания сохраняются как данные. BOM и первый обнаруженный тип межзаписных переводов сохраняются из загруженной копии; итоговый файл завершается переводом строки. Если рабочую копию отдельно пересохранить во внешнем редакторе, при продолжении используется её BOM/переводы, которые могут отличаться от исходника. Принудительное восстановление форматирования оригинала в таком случае отложено; текст полей от этого не меняется.

Запись выполняется во временный файл в том же каталоге, затем fsync и атомарная замена. При неудаче до замены прежнее решение остаётся в памяти, на экране ошибка, перехода к следующей записи нет. Если замена уже состоялась, но синхронизацию каталога диск не подтвердил, приложение явно сообщает об этом и останавливается на подтверждении: файл уже содержит решение, но его надёжность при сбое питания не подтверждена. Можно повторить запись; откатывать память к старым значениям в таком случае нельзя. Рабочая копия создаётся с правами только для владельца. Рядом остаётся маленький `.lock`: само наличие файла не означает активную блокировку; второй работающий экземпляр не сможет взять ту же блокировку.

**Не редактируйте рабочую копию в LibreOffice/OnlyOffice во время сеанса.** Программа обнаруживает внешние изменения перед сохранением, но обычные офисные редакторы не обязаны соблюдать её блокировку. После внешней правки выходите и запускайте приложение заново. Храните резервные копии своей работы. Оформление офисной таблицы CSV не хранит.

Сохранение рассчитано на локальный диск Linux. Реальное отключение питания и сетевые файловые системы не проверялись; тесты воспроизводят программные ошибки записи/синхронизации. Это не замена резервному копированию.

## Где учиться

Сначала [учебный маршрут](docs/learning.md), затем небольшое изменение в функции `render` в `src/ui.c`. Исходники разделены по назначению:

| Файл | Назначение |
|---|---|
| `src/main.c` | Аргументы запуска и соединение частей |
| `src/csv.c` | Чтение, проверка и запись формата CSV, кодировки |
| `src/store.c` | Рабочая копия, блокировка, атомарное сохранение |
| `src/guide.c` | Справочник категорий |
| `src/ui.c` | Экран и ручной сценарий |

Пока не нужно самостоятельно переписывать весь парсер или изучать все вызовы ncurses. Сначала используем инструмент, затем разбираем один путь данных за раз.

## Перенос на стационарный компьютер

Перенесите исходники (архив или Git) и выполните `make`. Готовый бинарник лучше пересобрать под установленную систему. Модели не нужны для этой версии. Данные храните на HDD и передавайте пути в аргументах. `.gitignore` исключает CSV вне демонстрационного примера, результаты, private/, векторы и модели. Перед любой публикацией проверяйте содержимое Git; эта версия никуда не отправлена.
