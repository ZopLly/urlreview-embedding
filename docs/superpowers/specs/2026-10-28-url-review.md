# Первая рабочая версия URL Review

28 октября 2026. Предложение для согласования перед реализацией.

## Назначение

Ускорить ручную разметку сайтов. Пользователь принимает решения самостоятельно. Помощник реализует основу, затем обучение C продолжается через небольшие изменения в ней. Работа полностью локальная. Настоящие CSV помощник не открывает: проверка только на вымышленных данных. Учебный `/home/andrew/projects/c-learning/projects/main.c` остаётся без изменений.

## Выбранный подход и альтернативы

Согласован смешанный формат: помощник реализует рабочую основу, ученик проверяет её и учится на отдельных частях. Последовательная учебная разработка с нуля слишком откладывает основную работу по разметке. Полностью автоматическая разметка не соответствует ручному сценарию. Для системы в целом выбран C для интерфейса и обработки разметки, Python для последующих локальных эмбеддингов. Реализация запуска нейросети непосредственно на C сейчас неоправданно сложна.

Первая версия включает ручное терминальное приложение. Эмбеддинги и оконный интерфейс — следующие этапы, не условия готовности этой версии. Поиск похожих позже вызывается отдельной командой и не заполняет разметку автоматически.

## Хранение и совместимость

- Отдельный каталог исходников: `/home/andrew/Документы/ChatGPT/работа/url-review`. Без установки системных пакетов и без изменения настроек офисных программ.
- C17, Linux, ncursesw для терминала с Unicode и прокруткой; установленная библиотека уже доступна. Сборка с `-Wall -Wextra -Wpedantic`.
- Входной файл и отдельная рабочая копия указываются при запуске. Исходный путь никогда не перезаписывается. Если рабочая копия уже существует, продолжаем из неё; подтверждаем совместимость с исходником сравнением заголовков, порядка и количества записей и всех полей кроме `action`/`label`. При несовпадении останавливаемся без записи.
- Кодировка выбирается явно: UTF-8 по умолчанию или Windows-1251. В памяти используется UTF-8 через iconv. Сохраняется выбранная кодировка; непредставимый символ вызывает ошибку, а не замену на `?`.
- Разделитель выбирается явно: `;` по умолчанию, также запятая и табуляция. При несовпадении настроек с файлом показываем понятную ошибку о заголовках, не угадываем данные.
- Нужны столбцы `domain`, `class`, `label`, `action`, `description`, в произвольном порядке. Повторяющиеся имена обязательных столбцов отклоняем. Дополнительные столбцы и все значения сохраняем. Исходные `class`, `domain`, `description` не изменяем.
- Настоящий CSV: кавычки, удвоенные кавычки, пустые и завершающие поля, разделители и переносы внутри кавычек, CRLF/LF, UTF-8 BOM. Одна запись может занимать несколько физических строк. Никакого фиксированного буфера описания в 256 байт. Неверный CSV отклоняем до первого сохранения. Количество полей каждой записи должно соответствовать заголовку.
- При записи допускается нормализация кавычек и переводов строк между записями. Содержимое всех полей, включая переводы строк внутри описания, сохраняется без изменений. BOM и тип перевода строк между записями сохраняются по исходному файлу; смешанные межзаписные переводы нормализуются к первому обнаруженному.
- Сохранение: временный файл в каталоге рабочей копии, проверка ошибок записи, fsync, атомарное переименование. При неудаче пользователь остаётся на записи с несохранённым решением и видит ошибку. Счётчик завершённых не увеличивается. Работающий экземпляр держит эксклюзивную блокировку рабочей копии; второй экземпляр не может сохранять поверх первого.
- Идентификатор записи внутри первой версии — её неизменяемая позиция в загруженном наборе, а не домен. Сортировки и удаления нет, повторяющиеся домены допустимы. Внешнее изменение рабочей копии после загрузки обнаруживается перед сохранением и блокирует запись.

## Экран и сценарий

Сверху всегда домен, исходный class, номер и прогресс. По центру полное описание с переносом по ширине экрана и прокруткой стрелками / PageUp / PageDown. Снизу доступные команды. Размер окна учитывается, слишком маленькое окно показывает просьбу увеличить терминал. Интерфейс не требует мыши.

1. При запуске открывается первая запись с пустым `action`. Известные заполненные значения: `OK`, `ERROR`, `NOT_DESC`; неизвестные непустые значения показываются как ошибка данных до изменения файла.
2. Пользователь выбирает действие 1/2/3, затем категории.
3. Постоянные номера категорий из отдельного локального справочника; английское имя и русское пояснение. Сохраняется только точное английское имя, несколько — через запятую. Выбор нескольких категорий клавишей Space, завершение Enter, отмена Escape. Поиск по имени можно оставить следующему этапу.
4. Для `OK` выбираются дополнительные категории, пустой выбор разрешён. Для `ERROR` выбираются правильные, пустой выбор разрешён при отсутствии подходящей. Для `NOT_DESC` пользователь явно попросил разрешить пустой выбор, хотя PDF требует категорию: это отличие отмечается в README и в справке статуса. Программа не выводит неизвестную категорию из домена и не исправляет `class`.
5. Экран подтверждения показывает действие и категории; Enter сохраняет, Escape возвращает к редактированию. Лишь после удачного сохранения переходим дальше.
6. Справка показывает критерии включения/исключения из предоставленного PDF. Это справочник задания, а не универсальная классификация; спорные гипотезы из журнала не становятся правилами.
7. «Назад» открывает предыдущую просмотренную запись в текущем сеансе. Правка проходит то же подтверждение и сохранение. Завершённость считается по количеству непустых допустимых `action`, а не по позиции.
8. «Отложить» не меняет CSV и пропускает запись до конца текущего прохода. После прохода отдельная команда возвращает отложенные; при следующем запуске пустые action снова доступны. Отложенные — состояние сеанса, отдельный файл прогресса не нужен.
9. При отсутствии непроверенных записей показываем итог и возможность вернуться к последним просмотренным. Выход не создаёт новых решений. Несохранённые изменения требуют выбора сохранить / отменить / продолжить редактирование.

## Проверка и обучение

Проверки на вымышленных CSV: UTF-8 и Windows-1251, длинное описание минимум 12000 символов, многострочные поля с кавычками, завершающие пустые столбцы, дополнительные столбцы, повторяющиеся домены, повреждённый CSV, неизвестный action, отсутствующие/повторные заголовки, запрещённая перезапись исходника, ранний выход, возобновление, отказ сохранения, конкурирующий экземпляр и внешнее изменение файла. После сохранения независимое чтение подтверждает точное содержимое полей. Тесты не используют реальные записи.

Проверяем терминальный сценарий на тестовых данных, включая изменение размеров окна, длинное описание, отмену выбора, несколько категорий, отложенные записи и возврат. Не заявляем готовность интерфейса только по успешной компиляции.

Поставляем исходники, Makefile, тестовые данные и команды запуска, README на русском и короткую карту учебных изменений. Настоящие данные и векторы исключаем из будущего Git-репозитория. GitHub ничего не публикуем без отдельного запроса.

Первое упражнение после готовности: найти функцию показа записи и самостоятельно изменить одну подпись, пересобрать и проверить. Затем разобрать путь «CSV → структура записи → экран → решение → CSV». Полное понимание указателей, парсера и ncurses не является предварительным условием использования приложения.

## Критерий готовности

Пользователь может собрать приложение, открыть вымышленный CSV, прочитать длинное описание, выбрать действие и категории, подтвердить, закрыть и продолжить с первой непроверенной записи. Изменены только action/label рабочей копии; содержимое остальных полей сохранено. Выполненные проверки и ограничения перечислены явно. Реальная польза оценивается пользователем на его компьютере; улучшение скорости разметки заранее не обещается.
