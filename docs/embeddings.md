# Локальные эмбеддинги: запуск и устройство

## Быстро попробовать на вымышленных данных

Из папки проекта запустите `./scripts/run-embedding-demo.sh`, затем нажмите P на экране записи. Скрипт готовит индекс только для демо; рабочий CSV не открывается. Нужна уже выполненная установка модели.

## На этом ноутбуке уже установлено

Модель и отдельное Python-окружение находятся в папке проекта. Модель multilingual-e5-small запускается на процессоре, четыре вычислительных потока. После установки для индекса и поиска интернет не нужен. Основная программа остаётся на C; Python используется только при подготовке индекса.

Сначала закончите текущую запись и выйдите из разметки через Q. Индекс готовим из рабочей копии: в ней уже есть ваши подтверждённые решения. Ниже `train_0_5000.csv` — имя рабочей копии из вашей команды; команды выполняете самостоятельно, помощник этот файл не открывал.

Из папки проекта:

```sh
./scripts/build-embeddings.sh train_0_5000.csv results/sites.uremb --encoding windows-1251 --delimiter ';'
```

Программа печатает прогресс. Длинные описания требуют больше времени, чем короткие; на 5000 сайтов время пока не измерялось. Ctrl+C отменяет подготовку, старый индекс и CSV сохраняются. Для UTF-8 уберите параметр `--encoding windows-1251`. Кодировка выбирается по фактическому файлу, а не операционной системе.

После успешного создания индекса запустите разметку со **старыми путями к исходнику и рабочей копии**, добавив `--embeddings`:

```sh
./url-review "$HOME/projects/train/train_0_5000 (Копия).csv" train_0_5000.csv --encoding windows-1251 --delimiter ';' --embeddings results/sites.uremb
```

P на экране записи открывает до пяти похожих проверенных примеров. Стрелки выбирают пример, Enter показывает принятую разметку и полное прокручиваемое описание, Q/Escape возвращает назад. Если введённая категория в label длинная, полное значение видно в подробностях. Class и label показаны отдельно: при OK class подтверждён, при ERROR правильные категории находятся в label; NOT_DESC и ERROR без установленной категории теперь исключаются из результатов поиска.

При новом подтверждённом решении пример автоматически становится доступным в поиске. Перезапускать вычисление эмбеддингов после каждой проверки не нужно. Непроверенные записи и сама текущая запись в результаты не входят. Пустое описание не участвует в поиске. Если доступно меньше пяти проверенных описаний, результатов будет меньше. Даже слабое сходство может попасть в список: порог качества пока не подбирался.

## Перенос на другой компьютер

Папки `.venv-embeddings` и `models` не входят в архив исходников и Git. Python-окружение не следует просто копировать между компьютерами. Нужен Python 3.11–3.13 с поддержкой venv/pip; проверено на Python 3.12.14.

Один раз, с интернетом:

```sh
./scripts/setup-embeddings.sh
```

Если установлен нужный Python под другим именем:

```sh
PYTHON_BIN=/путь/к/python3.12 ./scripts/setup-embeddings.sh
```

Скрипт создаёт отдельное окружение, устанавливает зависимости, скачивает примерно 135 МБ модели/токенизатора и проверяет их SHя фиксированная версия модели A-256. Он не открывает CSV. Используетс`614241f622f53c4eeff9890bdc4f31cfecc418b3` из [официального репозитория multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small), лицензия MIT. Для вычислений выбран опубликованный авторами репозитория ONNX INT8; его имя содержит avx512_vnni, но на этом ноутбуке он проверен через ONNX Runtime CPU без AVX-512. Другой процессор всё равно нужно проверить командой smoke, которую выполняет установка.

Для проверки без сети:

```sh
.venv-embeddings/bin/python embeddings/local_embeddings.py smoke
```

## Что происходит внутри — по шагам

**1. Описание превращается в токены.** Токен — часть текста, которую понимает модель: это может быть слово, кусочек слова или знак. Это не то же самое, что один символ или одно слово.

**2. Длинный текст делится на окна.** У этой модели предел 512 токенов на вход. Мы берём по 320 токенов описания, соседние окна пересекаются на 32 токена, добавляем префикс `query:` и специальные токены. На обеих сторонах используется query:, как рекомендует карточка E5 для симметричного сравнения. Последний фрагмент тоже обрабатывается. Исходное описание не сокращается и не переписывается; для вычисления нормализуются только пробелы.

**3. Модель выдаёт вектор.** Для каждого окна мы усредняем выходы модели по токенам и нормализуем полученный вектор. Затем усредняем векторы окон и снова нормализуем. Результат — 384 числа для одного сайта. Это компактное представление общего смысла, а не текстовый ответ модели.

Пример для понимания, не реальный результат: магазин инструментов можно представить как `[0.8, 0.2, 0.1]`, другой магазин — `[0.7, 0.3, 0.1]`, музыкальную школу — `[0.1, 0.2, 0.9]`. В нашей системе чисел 384, и у каждой координаты нет отдельного понятного названия вроде «музыка» или «магазин».

**4. Сравниваем направления векторов.** Косинусное сходство равно сумме попарных произведений координат, делённой на произведение длин векторов. Для нормализованных векторов длины близки к единице. Чем выше коэффициент, тем ближе модель считает общий смысл. `0.9` не означает «90% вероятности правильной разметки». У E5 даже разные тексты могут иметь высокие коэффициенты.

**5. C выбирает похожие проверенные записи.** Индекс содержит векторы всех описаний, включая ещё не проверенные. Перед показом программа отбирает только строки с OK либо ERROR с непустым исправленным label и использует актуальную разметку из открытой рабочей копии. Она не переносит категории автоматически.

**6. Индекс хранится отдельно.** Бинарный файл `.uremb` содержит заголовок, 384 числа на запись и отпечаток domain+description. Для 5000 записей это около 7.4 МиБ. Если поменять только action/label, индекс остаётся годен. Если изменить домен, описание, количество или порядок записей, приложение обнаружит несовпадение и попросит пересоздать индекс. Проверяется случайное рассогласование, а не подлинность файла против злоумышленника.

## Где находятся части программы

- `embeddings/local_embeddings.py`: токенизация, вычисление векторов, сохранение индекса. Только команда download обращается в сеть.
- `src/embedding.c`: проверка индекса, косинусное сходство, отбор пяти примеров.
- `src/ui.c`: экран P и просмотр примера.
- `src/store.c`: прежнее сохранение ручной разметки; модель в принятии решений не участвует.

## Границы первой версии

Это готовая предобученная модель, она не обучается на ваших новых решениях. С ростом разметки растёт число доступных примеров. Усреднение окон может смешивать разные темы страницы; повторяющиеся меню и списки товаров могут влиять на результат. Мы пока не измеряли качество на вашей разметке и не обещаем идеальное совпадение категорий. Следующий полезный шаг — самостоятельно проверить несколько известных случаев и обсудить, какие примеры оказались полезными, а какие нет.

## Индекс из XLSX

Построитель использует тот же OOXML-модуль, что приложение. Для нового файла создайте отдельный индекс:

```sh
./scripts/build-embeddings.sh '/home/andrew/projects/train/MAINTRAIN_checked.xlsx' 'results/MAINTRAIN.uremb'
./url-review '/home/andrew/projects/train/MAINTRAIN_checked.xlsx' 'results/MAINTRAIN_review.xlsx' --embeddings 'results/MAINTRAIN.uremb'
```

Если в книге несколько подходящих листов, передайте одинаковый `--sheet 'Имя листа'` обеим командам. Изменение только label/action не требует перестроения; изменение описаний, доменов, числа или порядка сайтов требует нового индекса. Номера физических пустых строк не меняют хеши описаний. Старый индекс от другой таблицы может быть несовместим.

Для повторяемой диагностики установленной модели на вымышленных данных: `.venv-embeddings/bin/python scripts/check-similarity.py`. [Что показала проверка](similarity-check.md).
