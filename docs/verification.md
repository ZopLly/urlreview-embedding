# Проверка первой рабочей версии

28 октября 2026. Настоящие CSV не открывались. Учебный проект не изменён.

## Выполнено

- Полная сборка с C17, `-Wall -Wextra -Wpedantic -Werror`: без предупреждений.
- `make test`: проверки ядра CSV/хранения, конкурентной внешней правки, синхронизации каталога, справочника и 12 интеграционных тестов Python — пройдены.
- Тесты терминального интерфейса запускают реальный ncurses-бинарник в PTY: несколько категорий, подтверждение, отмена, справка, переносы/длинный текст, resize, отложить/вернуть, назад/правка, продолжение после перезапуска и отказ незаметного сохранения при слишком маленьком окне.
- CSV проверяется независимо стандартным Python csv.reader: UTF-8/Windows-1251, три разделителя, LF/CRLF/CR, BOM, кавычки, пустые/завершающие поля, повторяющиеся домены и многострочные описания. Есть воспроизводимые случайные тестовые строки.
- ASan/UBSan ядра — пройдены. LeakSanitizer недоступен в sandbox под ptrace, поэтому выключен; отсутствие утечек отдельной проверкой не заявляется.
- Реальный `scripts/run-demo.sh`: загрузка полного справочника из 59 категорий, подтверждённое сохранение shopping/ERROR и переход к следующему вымышленному сайту — проверены; созданный проверкой результат удалён, чтобы демо пользователя началось с чистой копии.
- Масштабная проверка: 5000 вымышленных записей, 113563929 байт (~108 МиБ), проверка формата завершилась успешно за 1,18 с на текущем компьютере. Это измерение чтения/валидации, а не обещание скорости ручной работы или на другом ПК.

## Независимый обзор

Отдельный reviewer прочитал исходники и требования без изменения файлов и без доступа к настоящим CSV. Три значимых дефекта воспроизведены и исправлены:

1. Таблица и снимок рабочей копии теперь создаются из одного чтения, чтобы промежуточная внешняя правка не становилась незаметной базой для потери решения. Regression `test_race.c`: RED → GREEN.
2. В слишком маленьком окне запрещены выбор/сохранение; доступны только отмена/выход/изменение размера. Regression `test_small_window_does_not_confirm_unseen_decision`: RED → GREEN.
3. Различаются «не записано», «записано и синхронизировано», «файл заменён, но надёжность при сбое питания не подтверждена». Последнее состояние явно показывается, автоматический переход остановлен. Regression `test_sync.c`: RED → GREEN; реальный PTY проверяет предупреждение и успешную повторную попытку.

Обрезка длинного списка выбранных категорий при подтверждении повышена до значимого дефекта: перед сохранением пользователь должен иметь возможность увидеть весь список. Добавлена прокрутка. Regression с 30 длинными кодами в минимальном окне: RED → GREEN.

## Технические решения помощника

- Новый отдельный каталог и локальная ветка Git вместо worktree: существующего репозитория не было. Это сохраняет учебные файлы; при переносе нужен весь новый каталог. Ничего не опубликовано.
- Учёт задач — PROGRESS.md и локальные commits вместо вспомогательных skill-скриптов, предполагающих уже существующий worktree; на программу это не влияет.
- Лимит исходника 256 МиБ: предотвращает случайный неограниченный расход памяти; для большего файла потребуется изменить лимит/подход к чтению.
- При ошибке синхронизации после rename память отражает фактически заменённый файл; ложный откат запрещён, пользователь получает предупреждение и может повторить запись. Сохранность при немедленном отключении питания до успешной синхронизации не гарантируется.
- Проверялись локальные файловые операции и программно воспроизводимые ошибки; физическое отключение питания и сетевые файловые системы не проверялись. Для их гарантий нужны отдельные испытания.
- Reviewer проверил структуру справочника, не сравнивал смысл правил с PDF. Справочник сгенерирован напрямую из предоставленной таблицы с учётом страниц/колонок и выборочно сверен помощником; спорные гипотезы из журнала не включены. Критерии доступны по H для проверки пользователем.

## Небольшое отложенное отличие

Если пользователь вне приложения пересохранил совместимую рабочую копию с другим BOM/типом переводов между записями, при возобновлении используется форматирование этой копии, а не принудительно исходного файла. Точные значения полей, включая переносы внутри описания, сохраняются. Это описано в README; восстановление метаданных исходника отложено.
